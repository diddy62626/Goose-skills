# stdlib

**Working with data** — The standard library module by module: std, dictionary, vec/mat/quat, math, os, binary/base64, json, csv/regex.

8 skills. Load any of them as `stdlib/<skill>/skill.md`.

- [`goose-binary-base64`](binary-base64/skill.md) — binary and base64 modules — external binary formats, checked reads: > binary gives checked reads and appending writes of external formats, little- and big-endian, at offsets or with a cursor Reader and bounded subreaders; returned byte slices borrow the input. base64 is RFC 4648 standard alphabet encode/decode into a builder.
- [`goose-csv-regex`](csv-regex/skill.md) — csv and regex modules — RFC 4180 records, Rust-regex-style matching: > csv::each_record streams RFC 4180 records as zero-copy field slices with full quoting support; csv::format_field quotes where needed. regex has Rust-regex syntax and leftmost-first matching, complete DFAs compiled up front, find/matches/count/each_match/each_captures/format_replaced, with the supported syntax and known limits.
- [`goose-dictionary`](dictionary/skill.md) — dictionary — the hash map (and set): > dictionary<K, V> is an open-addressing map with linear probing, power-of- two capacity, backward-shift deletion and 31-bit hash tags per slot. Keys need hash + ==; string keys are const u8[:] views (nothing copied). get/ insert/get_or_insert/update/remove/each/reserve, and the shrink rule for references into the slot array.
- [`goose-json`](json/skill.md) — json module — writer, tree parser, and streaming reader onto your types: > JSON three ways: a writer appending values to a builder; a parser building a document tree (Node[>..] with relative links; keys are slices of the text, escapes decoded into a scratch builder); and a zero-build Reader mapping text directly onto the caller's types, serde-derive style, with sticky errors.
- [`goose-math-module`](math-module/skill.md) — math module — libm at both widths, constants, helpers: > math provides libm at both widths (sin picks sin/sinf by argument type), the constants PI/TAU/E/INF/NAN that adapt to context, helpers (radians, is_nan, is_finite, fract, inverse_lerp, smoothstep, wrap_angle), and mul_add with its FMA caveats (cancellation and overflow differences vs x*y+z).
- [`goose-os-module`](os-module/skill.md) — os module — files, args, env, time, stdin, resources: > A small interface to the runtime's OS layer: whole-file read/write (including atomic write), directory listing, stdin/stdout, args()/env(), time/clock/sleep, random_seed, trim_memory, and resource_dir() for application assets. Paths are UTF-8; no subprocesses or networking in v1.
- [`goose-std-algorithms`](std-algorithms/skill.md) — std module — array algorithms, sorting, hashing, rng: > The std module: HOF algorithms (map/filter/fold built in place), searching (find/find_index/position/binary_search/lower_bound), in-place transforms (sort pdqsort, stable_sort merge), length changes (insert_at/remove_at/ swap_remove/retain/dedup/heap_*), hashing (hash/hash_combine, user key types), and splitmix64 rng.
- [`goose-vec-mat-quat`](vec-mat-quat/skill.md) — vec, mat, quat — the numeric geometry modules: > vec2/3/4<T> generic vectors (float2/3/4, double*, int* aliases) with language memberwise operators; mat as column-major GLSL matrices with transform builders (translate/rotate/perspective/ortho/look_at, right- handed, depth 0..1); quat rotations with angle_axis/slerp/from_euler and mat conversions; compose() builds model matrices.
