# functions

**Core concepts** — Functions, generics, function values and blocks, nested functions, recursion, qualifiers.

6 skills. Load any of them as `functions/<skill>/skill.md`.

- [`goose-function-qualifiers`](function-qualifiers/skill.md) — Function qualifiers — inline, simd, checkfree, thread_fn, extern, export: > The qualifier vocabulary and their fixed order: export/extern first, then checkfree, simd, inline, recursive, and fn/thread_fn. What inline forces, what simd builds (per instruction-set level), what checkfree guarantees, and which combinations are forbidden.
- [`goose-function-values-blocks`](function-values-blocks/skill.md) — Function values and trailing blocks — HOFs without closures: > Function values are compile-time entities passed as generic parameters — never runtime data, never stored or returned. A trailing block { ... } is the last argument (implicit it, or a, b =>). Blocks read/write enclosing locals, and a return inside a block returns from the LEXICALLY ENCLOSING function — a hand-written iterator has for's control power.
- [`goose-functions-parameters-results`](functions-parameters-results/skill.md) — Functions — parameters, defaults, multiple results, overloading: > Free functions with UFCS method syntax. Parameters are let bindings (var for reassignable); reference/slice/by-value parameter kinds; trailing default parameters evaluated per call; multiple results as a calling convention (-> A, B; let a, b = f()); overload resolution rules and order-independence; inferred result types and in-place returns.
- [`goose-generics`](generics/skill.md) — Generics — untyped parameters, <T>, monomorphization, no trait bounds: > An untyped parameter is generic; <T> says two parameters agree or names a type no parameter carries. Everything is monomorphized: a generic body is checked only at concrete instantiations, with the compile-time call chain reported. Type argument inference, explicit lists, literal parameters, floating context, and .='s move semantics in generic code.
- [`goose-nested-functions`](nested-functions/skill.md) — Nested functions — shared-state parsers without context structs: > A fn declared inside a fn reads and writes the enclosing function's locals as free variables. Nested functions of one block may call each other in either order (recursive-descent parsers), overload like top-level ones, and are compile-time entities. When to nest vs pass a context struct.
- [`goose-recursion`](recursion/skill.md) — Recursion — recursive fn, the growable-data rule, shared scratch: > Recursion is opt-in: mark the cycle's entry recursive fn, write out every signature in the cycle, and no function in the cycle may hold growable data across a call back into the cycle. Three workarounds: pass the accumulator in, scope the scratch to end before the call, share one grow-shrink stack truncated to a mark. Plus the detailed rules.
