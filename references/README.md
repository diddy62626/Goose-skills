# references

**Core concepts** — References and UFCS, optionals and narrowing, lifetimes/roots, relative references, const.

5 skills. Load any of them as `references/<skill>/skill.md`.

- [`goose-const-writability`](references/const-writability/skill.md) — const and writability — read-only contents, slots, inference: > Everything is writable unless its type says otherwise. const T is a value whose contents cannot be written; writability is inferred per instantiation; parameters are generic over constness; slots (fields, elements, globals) say what they may hold. const is shallow.
- [`goose-lifetimes-roots`](references/lifetimes-roots/skill.md) — Lifetimes — roots, stores, and reading the errors: > Goose's entire "borrow checker" is one rule: a reference must not outlive the variable that owns its target, and must never observe its target at a wrong type. No annotations, no exclusivity. Roots are inferred and functions are specialized per root. The store/return/branches/rebinding/ temporary/holder rules, and how to read the two-ended error messages.
- [`goose-optionals-and-narrowing`](references/optionals-and-narrowing/skill.md) — Optionals — T?, null, and narrowing with if/while/guard/assert: > T? is a nullable reference with no space cost (null is address 0). It is not transparent: narrow it with if/while/guard/assert or a comparison with null; inside the narrowed region it IS a T&. Covers rebinding semantics, while-loops over linked lists, and the null-returning library idioms.
- [`goose-references-and-ufcs`](references/references-and-ufcs/skill.md) — References — transparent, .= binding, &x, UFCS method syntax: > T& is a machine address with no arithmetic and no way to dangle. References are transparent (behave as their target everywhere; no * or ->). .= binds/rebinds a reference itself, .== compares addresses. &x makes a reference; reference destinations bind without &. UFCS: x.f(a) calls f(x, a).
- [`goose-relative-references`](references/relative-references/skill.md) — Relative references — narrow links, pool-relative, and `self`: > A relative reference stores a link as a narrow offset (u8/u16/u32/u64/ varint) instead of an 8-byte address. Self-relative (same array, position-independent, serializable) vs pool-relative (T&<u32 in pool>, other arrays can link in). T&<u32>? makes offset 0 the null. self builds sentinels; copying rules for values holding self-relative links.
